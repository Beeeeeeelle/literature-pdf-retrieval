# 找全文：策略、接力和核对

[返回简介](../README.zh-CN.md) · [可执行 skill](../literature-pdf-retrieval/SKILL.md)

## 先看手上有什么，再决定下一步

拿到清单后，先检查稳定 ID、标题、DOI、已有文件和以前试过的路径。缺 DOI 不代表找不到：可以先用完整标题与作者查官方元数据。已有 PDF 也不代表找对了：要先核对身份，避免把错文带进后面的编码。

| 观察到什么 | 接下来怎么做 | 为什么 |
|---|---|---|
| DOI 缺失、旧链接失效 | 补元数据，保留标题变体，寻找官方仓储入口 | 先提高匹配准确性，减少无效下载 |
| 有公开全文 | 优先尝试出版社开放文件、仓储和其他合法公开来源 | 通常不需要人介入 |
| 直接访问失败，用户有机构访问条件 | 查官方图书馆目录、解析入口与馆藏信息，再尝试相应路径 | 直接付费页面不一定是唯一入口 |
| 有图书馆入口，但实际权限未确认 | 把它作为待尝试的路径，依据访问结果更新状态 | 馆藏链接不等于已授权，也不等于已拿到文件 |
| 页面能打开，工具无法保存 | 给人文章入口、文件命名与交回位置 | 把剩下的一小步交代清楚 |
| 没有订阅或当前路径失败 | 查作者/机构公开版本，或整理可选的图书馆服务入口 | 让下一次尝试有依据；不自行下单或发请求 |
| 429、验证码、反爬挑战或反复登录 | 停止该路径，记录原因，换可用来源 | 避免重复无效操作 |
| 文件回来了 | 检查结构、身份、版本与完整性，记录页数和哈希 | 手动下载也可能得到错文或匿名稿 |

具体平台路径是经验线索，不保证长期有效。先确认页面和工具实际支持什么，再执行；不要把旧案例中的机构权限当成新用户的权限。

## 人在流程里的位置

这里的 human in the loop 有两类工作：**访问操作**和**证据判断**。

访问操作包括登录、MFA、保存文件再交回。Agent 应该先整理好文章 ID、入口、已经试过的路径、遇到的障碍和返回位置。人完成这一小步后，Agent 接着核对并更新队列；其他能获取的文章可以继续处理。

证据判断包括多版本取舍、章节是否完整、题名相近的报告是否对应。同一个人可以做两类工作，但日志不能把“人下载了”写成“人确认了身份”。没有实际人工确认，就保留待处理状态。

一个清楚的交接可以这样写：

> R017 的图书馆入口已到登录页，文件还没拿到。请打开这条文章入口，登录后保存 PDF，放到约定文件夹并命名为 R017.pdf。收到后我会核对标题、DOI 和页数，再更新清单。

这个例子只是交接模板。真实任务需要填写经过检查的文章入口，不使用猜测的网址。

## 案例里真正观察到了什么

Agency 项目的记录包含公开来源、Purdue 图书馆路径以及手动浏览器保存的文件。历史队列中确有“图书馆可访问，但需要保存后交回”的节点：发现资源、获取文件和核对文件是不同的步骤。来源标签本身不能证明是谁点击、用了多少时间，或那条路径在今天仍然可用。

2026-09-25 对当前 130 份文件的复核没有发现结构损坏、跨 ID 重复哈希或孤立文件。默认解析器得到 127 条身份通过、3 条疑点。第二解析器在 2 份文件中找到了预期 DOI；另一份虽题名对应，却保留匿名作者和占位 DOI，因此仍需版本核对。原有记录与后续复核分别保留，没有把旧状态改写成一次完美的自动流程。

这不是“找齐率 100%”的泛化证据。下载覆盖、身份确认、版本确认和综述纳入有各自的分母。TALL 历史综述的全文获取数字属于另一阶段、另一套记录，也不能拿来当这个独立 skill 的测试结果。

## 为什么单独做成 skill

全文获取常常可以独立发生：准备一次读书会、修复资料夹、补一篇论文的引用，都不需要开启整套综述审阅。因此，这个仓库保存检索与核对的具体策略；[Review Evidence Workflow](https://github.com/Beeeeeeelle/review-evidence-workflow) 只接收已核对的来源、尝试记录和剩余队列。

方法论文章应解释这些设计如何分配人和 AI 的工作，并报告可观察的记录与边界。平台地址、命令和逐步操作放在 skill 文档里，避免挤占论文主线。
